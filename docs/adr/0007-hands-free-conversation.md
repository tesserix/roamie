# Hands-free conversation on mobile

Roamie keeps its authenticated one-turn translation API and adds a foreground-only listening loop on iOS and Android. One conversation has at most one request in flight. At 64 kbps, a 30-second turn is about 240 KB (320 KB after base64); ten turns per minute would be 0.17 requests/second per active conversation. Aggregate demand depends on active users and is not yet measured. No new datastore, service, or retained audio history is introduced.

The device samples recording levels every 100 ms, requires 300 ms of voice-level sound, and ends a turn after 1.2 seconds of quiet or 30 seconds total. Thirty seconds without speech stops the session without submitting silence. The local endpoint-detection target is 1.3 seconds after a pause; backend and voice-engine latency remain additional and need device measurements. Energy detection is not speaker diarization: background music and loud surroundings can trigger it. Real-device acoustic validation is required before calling this production-ready.

Listening stays off during translation and speech playback. Playback completion, not speech submission, unlocks the next recording, with a 350 ms echo tail. Stop, blur, backgrounding, and microphone interruptions end the session. Permission, metering, network, and playback failures pause with an actionable message; there is no automatic request retry loop. Quiet mode shows text without spoken playback. Manual recording remains available, including on web where the recording module does not provide native metering.

This is reversible client code with no data migration or infrastructure rollout. Streaming recognition and duplex audio would need another audio transport and echo cancellation; retain the existing turn API until those capabilities are separately validated. Cost remains one existing model call per detected turn, bounded locally by serial processing and the idle timeout. No availability claim beyond the existing API is introduced.
